Run these in a terminal, not in this web page. Azure CLI 2.66+ is required. The load command group is preview.

The load extension may use the active CLI subscription even with --subscription. Load operations are blocked on a mismatch. Select CLI subscription changes that profile only after confirmation. For isolation, authenticate a separate AZURE_CONFIG_DIR before starting this app.

THE LIFECYCLE

A test definition is not a test run.

Show the YAML and the CLI that creates its test definition, then start separately identified executions. Preview every command before running it.

Applies to List test definitions only. The preview, copied command and step script use the selected CLI output format.

Polls test-run show every 10 seconds. Closing the UI does not stop Azure.

WHAT THE LOAD GENERATOR SEES

Client performance vs. engine health

LoadTestRunMetrics measures requests. EngineHealthMetrics measures load generators, not your app servers.

Choose the test/run on the left, then preview and execute Get all client metrics to see every available client metric together. This only reads the selected run; it does not start a load test.

All client metrics

One-minute buckets using CLI/service defaults. Values describe returned buckets, not whole-run totals. Missing datapoints are not assumed to be zero.

WHAT THE APPLICATION SEES

App components are monitored Azure resources.

An App Service, its App Service plan, SQL, or Application Insights can be a component. Listing components or server-metric configuration does not return metric values. Values come from Azure Monitor.

Inspect this resource to resolve its name/type before attaching it to the test.

Attach components and metric definitions before starting a run for repeatable Load Testing configuration. Azure Monitor reads also work directly on a resource without attaching it. Old metric values may have expired.
